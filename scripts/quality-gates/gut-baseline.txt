# Quality-gate floors. `scripts/gates.sh` reads this; nothing else does.
#
# These are FLOORS, not expected values: the run fails if it collects FEWER
# scripts, tests, gate scripts or gate self-tests than this. That is the
# silent-skip guard — a GDScript parse error makes GUT drop a whole test file
# while still reporting a green suite, and a glob that stops matching makes a
# Python gate stage announce itself and inspect nothing. A count that only ever
# rises is the cheapest way to notice either.
#
# WHAT ENFORCES THESE: only `bash scripts/gates.sh`, run by hand. Neither
# .husky/pre-push nor .github/workflows reads this file — they check "Failing
# Tests 0" and never look at the counts. So a deleted or parse-skipped test file
# passes both of them; the floor catches it only if someone runs the script.
#
# UPDATE IT DELIBERATELY, in the same commit as the change that moves it:
#   - added a test file      -> raise scripts
#   - added tests            -> raise tests
#   - added a check_*.py     -> raise gates
#   - added gate self-tests  -> raise gate_tests
#   - DELETED a test on purpose (see gut-tdd: a test pinning no behavior should
#     be deleted) -> LOWER tests, and say so in the commit message
#
# It lives in its own tracked file rather than inside gates.sh so that moving
# the floor is a reviewable one-line diff someone has to justify, instead of an
# edit buried in a script. This floor has gone stale four times (68/1083, then
# 79/1287, then 1293 after tests were deliberately removed, then scripts=89
# while the suite already collected 90); each time it either passed a real
# regression or failed honest work.
scripts=90
tests=1289
gates=6
gate_tests=260
